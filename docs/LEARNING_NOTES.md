## 第一阶段需要理解的概念

数据来源：[FashionMNIST 官方仓库](https://github.com/zalandoresearch/fashion-mnist)。数据包含 60,000 张训练图片和 10,000 张测试图片，每张都是 28×28 像素的灰度图，共有 10 类。

- **图片**：分类模型的输入。灰度图只有一个颜色通道，原始像素用 0–255 表示亮度，0 是黑色，255 是白色。
- **标签**：数据集已经提供的真实类别，编号从 0 到 9。例如 9 表示短靴。编号是类别的代号，不表示大小、优劣或置信度。
- **分类任务**：让模型根据图片，从 10 个类别中预测一个类别，再与真实标签比较。

| 标签 | 图中的英文名称 | 中文含义 |
| --- | --- | --- |
| 0 | T-shirt/top | T 恤／上衣 |
| 1 | Trouser | 裤子 |
| 2 | Pullover | 套头衫 |
| 3 | Dress | 连衣裙 |
| 4 | Coat | 外套 |
| 5 | Sandal | 凉鞋 |
| 6 | Shirt | 衬衫 |
| 7 | Sneaker | 运动鞋 |
| 8 | Bag | 包 |
| 9 | Ankle boot | 短靴 |

脚本展示训练集的前 9 个样本，样本编号为 0–8。样本编号与类别标签是两回事：编号定位某一张图片，标签说明它属于哪一类。这 9 张图片可能包含重复类别，并不保证覆盖全部 10 类。

### 读懂脚本的关键位置

- `Path(__file__).resolve().parent.parent`：从 `src/show_samples.py` 找到项目目录。
- `FashionMNIST(..., train=True, download=True)`：选择训练集，缺少数据时自动下载。`train=True` 只选择数据集，不启动训练。
- `dataset[index]`：按样本编号取出 `(image, label)`，即图片和真实标签。

### 张量与批次

- `ToTensor()` 把单张 FashionMNIST 灰度图片转为 `torch.float32` 张量，形状为 `[1, 28, 28]`。`1` 表示一个灰度通道，后两个数表示高度与宽度。
- 像素值由原始的 `0–255` 缩放到 `[0, 1]`；当前不做额外的标准化。
- **batch（批次）**：一次取出的一组样本。`batch_size=64` 时，第一批图片形状为 `[64, 1, 28, 28]`，标签形状为 `[64]`；第 i 张图片对应第 i 个标签。
- **shuffle（打乱顺序）**：只改变读取顺序，图片及其标签始终一起移动。训练集开启打乱，验证集和测试集保持顺序。
- `num_workers=0` 表示由当前 Python 进程读取数据，方便初学阶段在 macOS 上运行和调试。
- 不丢弃最后一批数据，因此最后一批可能少于 64 张。

### 训练、验证、测试的作用

| 数据部分 | 数量 | 来源与用途 |
| --- | --- | --- |
| 训练集 | 50,000 | 从官方训练集划分，后续用于学习模型参数 |
| 验证集 | 10,000 | 从官方训练集划分，后续用于比较模型方案、调整设置 |
| 测试集 | 10,000 | 独立的官方测试集，保留给最终评估 |

`random_split` 使用种子 42。检查脚本验证训练与验证索引没有重叠，并且完整覆盖原来的 60,000 张训练图片。这里检查的是样本索引，不是要求两部分的类别不同。

训练批次使用独立的、同样设为 42 的随机数生成器。因此重新运行可复现第一批图片；对同一个训练 DataLoader 进行下一轮遍历时，顺序仍会重新打乱。

### 为什么是 784 → 128 → 10？

| 层 | 对批次的处理 | 输出形状 |
| --- | --- | --- |
| 输入 | 每张图片是一个通道、28 行、28 列 | `[B, 1, 28, 28]` |
| `Flatten` | 将每张图片的 784 个像素展开成一列数，保留批次维度 | `[B, 784]` |
| `Linear(784, 128)` | 通过权重和偏置，将 784 个输入组合成 128 个中间数值 | `[B, 128]` |
| `ReLU` | 逐个处理数值：负数变为 0，非负数保持不变 | `[B, 128]` |
| `Linear(128, 10)` | 将中间特征组合成对应 10 个服装类别的分数 | `[B, 10]` |

`B` 表示实际批次大小，模型不会把它固定为 64。784 来自 `1×28×28`；128 是本次选定的隐藏层宽度，可以在以后的模型比较中调整；10 来自数据集的类别数量。128 个中间数值不是 128 个服装类别。

ReLU 的计算是 `max(0, x)`，例如 `[-2, 0, 3]` 变为 `[0, 0, 3]`。它引入非线性，让多层网络能表达更复杂的关系；如果两层线性变换之间没有非线性操作，组合后仍相当于一次线性变换。

### 输出分数与识别能力

最终的 10 个数叫原始类别分数（logits）。它们可以是负数，也不要求加起来等于 1，因此不能读成概率。`argmax` 选择最大分数所在的类别编号。

模型初始权重和偏置是随机生成的。给定图片和这些参数，数学计算就能得到分数，但参数尚未从数据中学到稳定的图片与类别关系。即使某一张图片碰巧预测正确，也不能据此认为模型已经学会识别；识别能力需要后续训练和独立数据上的评估。

### 前向计算与训练

- **前向计算**：使用当前参数，把输入图片变成输出分数。
- **训练**：先前向计算，再用真实标签计算损失，通过反向传播计算梯度，最后由优化器更新参数。
- 本步骤使用 `torch.no_grad()`，不记录用于反向传播的计算图。脚本比较计算前后的参数，并确认没有参数梯度；没有优化器或训练循环。
- `model.eval()` 切换到评估模式，并不会替代 `torch.no_grad()`。当前模型只有 Flatten、Linear 和 ReLU，评估模式不会改变这些层的计算。

模型共有 101,770 个可训练参数：第一层为 `784×128+128=100,480`，最后一层为 `128×10+10=1,290`。Flatten 和 ReLU 没有可训练参数。“可训练”表示后续可以学习这些参数，本步骤没有更新它们。

1. **前向计算**：`scores = model(images)`。这次需要保留计算图，因此不使用 `torch.no_grad()`。分数形状为 `[64, 10]`，此时参数和参数梯度都没有变化。
2. **损失计算**：`CrossEntropyLoss(scores, labels)`。输入原始类别分数与真实类别编号，返回一个表示本批次平均损失的标量；无需先计算 Softmax 或取预测类别。计算损失仍不会更新参数。
3. **反向传播**：`loss.backward()`。计算损失对参数的梯度，并写入参数的 `.grad`；权重值保持不变。
4. **优化器更新**：`optimizer.step()`。本演示使用学习率 0.1 的 SGD，没有动量或权重衰减，更新公式为 `新权重 = 旧权重 - 0.1 × 梯度`。

跟踪的权重是最后一层 `weight[8, 0]`：第 0 个隐藏特征连接到类别 8（Bag）的权重。它的梯度来自整个 64 张图片的平均损失。脚本在反向传播前、反向传播后和 step 后分别打印同一个权重及其梯度，并比较全部参数，验证前两步和反向传播都没有修改参数，step 后的数值符合公式。

`optimizer.zero_grad(set_to_none=True)` 清除旧梯度。因为 PyTorch 会累积梯度，正式训练时每次新更新前都要清理。`step()` 本身不会清空梯度，演示也会打印并验证这一点。最后用 `torch.no_grad()` 观察同一批次更新后的损失，不进行第二次更新；这不是验证集或测试集成绩。

- **CrossEntropyLoss**：将原始类别分数和真实类别编号转换为分类损失，默认取整个批次的平均值。它内部完成所需的分数转换，输入前无需添加 Softmax。
- **梯度**：损失对参数的导数，描述该参数小幅改变时对损失的局部影响。`backward()` 将梯度写入 `.grad`，不更新参数。
- **学习率**：控制每次更新的幅度。本次为 0.01；步长还取决于梯度的大小。
- **SGD**：使用当前批次已经计算好的梯度，执行 `新权重 = 旧权重 - 学习率 × 梯度`。本次不使用动量或权重衰减。

第一层权重用 `detach().clone()` 保存独立副本，检查前向计算和反向传播后都未变化。反向传播后打印第一层梯度形状及 L2 范数，选择绝对梯度最大的非零元素，记录索引、更新前值、梯度和更新后值，并允许浮点误差验证更新公式。对整个第一层也进行公式核对。

本次实际观察：同一训练批次的平均损失从 `2.297107935` 变为 `2.286031008`。只运行了这一次更新，没有根据损失结果重跑或挑选批次。损失下降只反映当前批次，不能说明对新数据的表现。

`outputs/one_step_predictions.png` 展示该批次前 9 张图片、真实类别和**更新前**记录的预测类别。图标题注明“训练前预测 / Pre-training predictions”，说明这些预测来自随机初始化，不是训练成果。模型只进行了一次更新，不能据此认为已经学会识别。中文标题使用当前 Mac 已有的 Arial Unicode MS 字体，无需安装字体或依赖。

`save_predictions()` 只负责绘图，可使用已记录的预测重绘图片，不创建模型或更新参数。本次复核只校对标题并重绘，没有重新执行训练步骤；先前的损失和权重数值保持为原始运行记录。临时模型没有保存为参数文件，已有模型定义和数据加载逻辑保留。

### 哪些数值会改变？

- 前向计算产生分数，损失计算产生一个平均损失值；它们不会修改权重。
- `loss.backward()` 把计算出的梯度写入参数的 `.grad`，权重仍不变。
- `optimizer.step()` 根据梯度更新两层 Linear 的权重和偏置。它使用 `model.parameters()` 中的参数；当前 SGD 没有动量或权重衰减，梯度为 0 的元素保持不变。
- 第一层权重形状为 `[128, 784]`、偏置为 `[128]`；最后一层权重形状为 `[10, 128]`、偏置为 `[10]`。Flatten 和 ReLU 没有可训练参数。

已有验证中，第一层权重 `(52, 441)` 在前向及 backward 后均为 `-0.028974475`；梯度为 `-0.016554644`，学习率为 `0.01`。step 按 `旧值 - 0.01 × 梯度` 将它改为 `-0.028808929`，浮点误差约 `1.304e-10`。负梯度使这次权重更新的方向为增大，具体改动幅度由学习率与梯度共同决定。

### 训练与验证流程

1. 用临时模型运行 3 个训练批次、2 个验证批次，确认训练改变参数，验证不改变参数或已有梯度；随后丢弃临时模型。
2. 重新设置种子 42，新建 CPU 模型、SGD 优化器和 DataLoader，正式开始训练。
3. 每轮调用 `model.train()`；每批依次执行清空梯度、前向计算、CrossEntropyLoss、反向传播、SGD 更新。损失函数直接接收原始分数，无需 Softmax。
4. 每轮结束调用 `model.eval()`，在 `torch.no_grad()` 内完整遍历验证集；下一轮训练再次调用 `model.train()`。
5. 按验证准确率选择最佳模型，仅严格提高时保存。准确率相同保留先出现的一轮。
6. 训练完成后，新建同结构模型，加载最佳 `state_dict`，在完整验证集重新计算指标并核对，随后展示固定的前 9 张验证图片。

每轮损失为 `Σ(批次平均损失 × 该批实际样本数) ÷ 总样本数`，准确率为 `预测正确数 ÷ 总样本数`。每轮读取 50,000 张训练图片、10,000 张验证图片；最后一批均为 16 张，也参与统计。

训练曲线的训练指标是在各批更新前累计的，模型在一轮中不断变化；验证指标来自该轮全部更新完成后的模型。因此第一轮验证准确率高于训练准确率，并不表示统计有错误。

### 理解本阶段

- **epoch（轮）**：完整遍历训练集一次。本次每轮使用 50,000 张训练图片。
- **batch（批次）**：一次共同计算损失和梯度的一组图片。本次通常 64 张；每个训练批次更新一次参数。
- **每轮验证**：观察未参与参数更新的图片上的表现，并用于选择保存哪轮模型。验证不更新参数，但选择最佳模型会使用验证结果。
- **曲线的含义**：本次训练与验证损失整体下降，准确率提高，说明模型在这两部分数据上的指标得到改善。这 5 轮未出现明显的训练改善而验证持续变差的趋势。
- **当前判断的边界**：曲线不能保证每个类别都识别良好，也不能给出官方测试集或真实拍摄图片的成绩；继续训练是否还会改善表现，仍需实际验证。

| 操作 | 输出形状 |
| --- | --- |
| 输入灰度图片 | `[B, 1, 28, 28]` |
| `Conv2d(1, 16, 3, padding=1)` + ReLU | `[B, 16, 28, 28]` |
| `MaxPool2d(2)` | `[B, 16, 14, 14]` |
| `Conv2d(16, 32, 3, padding=1)` + ReLU | `[B, 32, 14, 14]` |
| `MaxPool2d(2)` | `[B, 32, 7, 7]` |
| Flatten | `[B, 1568]` |
| `Linear(1568, 64)` + ReLU | `[B, 64]` |
| `Linear(64, 10)` | `[B, 10]` |

- **卷积**：用可学习的 3×3 小窗口在图片各处计算，同一组权重在不同位置重复使用。它可以学习局部明暗变化、轮廓等特征。第二次卷积组合前一层的 16 个通道，得到 32 个新的特征通道。
- **特征图**：记录某组卷积计算在各位置的响应。16、32 是特征通道数，不是颜色数量或类别数量；单张原图仍是一张灰度图。
- **padding=1**：在边缘补一圈零，使这两次步长为 1 的 3×3 卷积保持高度、宽度。
- **最大池化**：每个 2×2 区域保留最大值，宽高减半，通道数保持不变；本次从 28×28 变为 14×14，再变为 7×7。
- **最后的全连接层**：把 `32×7×7=1568` 个特征数值展开并组合为 64 个中间值，再生成 10 个原始类别分数。CrossEntropyLoss 直接接收这些分数，不提前加 Softmax。

实际首批 `B=64`，全部层形状与上述表格一致；ReLU 不改变形状。可训练参数为 **105,866**：两层卷积分别 160、4,640，两层全连接分别 100,416、650。ReLU、池化和 Flatten 没有可训练参数。

### 学习率变化带来的实际现象

SGD 的更新为 `新参数 = 旧参数 - 学习率 × 梯度`。在梯度相同时，0.03 的单次改动是 0.003 的 10 倍；但更新以后模型不同，后续梯度也会改变，因此准确率不会按这个倍数增长。

本次较大的 0.03 前期进展更快：第 5 轮三组验证准确率依次为 75.53%、81.03%、84.42%；固定十五轮后，0.003 的最佳成绩仍低于另两组。0.03 相对 0.01 的最佳准确率提高 2.07 个百分点，Shirt 召回率提高约 2.90 个百分点，Shirt → Pullover 减少 9 张。Shirt 仍是最弱类别。

| Shirt正确 / 实际数量 | 783 / 1,033 | 756 / 1,000 |
| Shirt召回率 | 75.80% | 75.60% |

测试Shirt→Pullover共55张。测试准确率比验证低0.01个百分点；这只是两份不同数据上同一模型的实际成绩差，不能用如此小的差距证明过拟合、完全泛化或统计显著性。测试交叉熵略高；交叉熵还取决于模型给真实类别的分数分布，准确率只看最高分类分数对应的类别，两者并非同一个指标。

### 每类测试指标

precision = 该类分对数 / 预测为该类的数量；recall = 该类分对数 / 该类实际数量；F1是precision和recall的调和平均。分母为0时脚本记0，本次每类都有实际样本和预测，不存在这种情形。

| 类别 | 实际数量 | 分对数量 | Precision | Recall | F1 |

| T-shirt/top | 1,000 | 876 | 86.31% | 87.60% | 86.95% |
| Trouser | 1,000 | 987 | 99.20% | 98.70% | 98.95% |

### 混淆矩阵与主要错误

混淆矩阵的**行是真实类别，列是预测类别**；对角线是分对数量。例如Shirt行、Pullover列的55，表示55张真实Shirt被错分为Pullover。两个方向分别统计，不能合并解释。

| 真实类别 → 预测类别 | 数量 |
| --- | --- |
| Shirt → T-shirt/top | 97 |
| T-shirt/top → Shirt | 85 |
| Pullover → Coat | 62 |
| Shirt → Coat | 60 |
| Pullover → Shirt | 56 |

测试集整体约每100张能分对92张，但Shirt只有约76张能分对。统计显示主要错误集中在外形接近的上衣类别；具体是否由轮廓、领口细节或28×28分辨率造成，仍属于待实验确认的猜测。

错误图覆盖数量最多的五种有向混淆，每种按官方测试顺序取前3张，再顺序补足16张；不按外观挑选。样例用于说明主要错误类型，未按发生频率抽样，因此不能根据图中某类出现次数估计整体错误比例。

### 实际运行和一致性检查
